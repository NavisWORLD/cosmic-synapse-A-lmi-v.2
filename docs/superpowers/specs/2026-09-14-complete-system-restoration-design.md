# COSMIC SYNAPSE // A-LMI Complete System Restoration Design

## Purpose

Restore the existing repository as both a runnable research/software package and a preserved historical archive. Modernization must not erase lineage, rewrite Git history, silently discard duplicate generations, or upgrade theory/speculation into verified claims.

## Architecture boundary

The active layer is organized conceptually as:

`SENSORS / INPUT -> NORMALIZED EVENTS -> CANONICAL TOKEN / STATE -> ADAPTIVE CST STATE -> MEMORY + KNOWLEDGE -> REASONING / MODEL PROVIDERS -> ORCHESTRATION -> POLICY / AUTHORITY -> TOOLS / OUTPUT -> WORLD`

Models are replaceable components. Persistent memory/state is inspectable and external to model parameters. Sensor acquisition is separate from reasoning. Model output has no implicit tool or actuator authority.

## Restoration strategy

1. Preserve repository history and inventory historical generations without deleting them.
2. Establish deterministic software-only CI that does not require external infrastructure or hardware.
3. Repair active A-LMI contracts: configuration, LightToken spectral representation, password encryption, raw artifact persistence, multimodal encoding semantics, temporal graph ingestion/retrieval, optional audio behavior, and hypothesis provenance.
4. Repair HRCS protocol/crypto/acoustic/mesh behavior and add an in-memory modem for deterministic end-to-end testing. RF frequency hopping remains experimental unless an interoperable schedule is actually integrated.
5. Preserve CST equations and historical names while describing 12D/x12/m12 as internal computational simulation state. Add deterministic state/replay tests around a canonical active engine without deleting prior generations.
6. Repair/version Python <-> Unity IPC and keep Unity optional.
7. Package minimal, development, ML, audio, infrastructure, HRCS, visualization, Unity/native-adjacent dependency groups separately.
8. Rewrite active documentation around receipts, provenance, limitations, reproducibility, security boundaries, and migration paths.
9. Run progressively stronger gates: unit -> deterministic integration -> package/install -> Docker config -> external-service integration -> optional hardware. Unavailable gates are reported as blocked/optional, never fabricated.

## Scientific and security discipline

- A one-dimensional FFT over embedding coordinates is an **embedding spectral transform**, not a Graph Fourier Transform.
- CLIP text/image native embeddings are aligned by CLIP; WavLM audio is a different embedding space unless a documented trained alignment is loaded.
- HRCS ChaCha20-Poly1305 with a pre-shared/static derived key provides authenticated encryption, not forward secrecy.
- Weighted averaging plus optional noise is not cryptographic secure aggregation and is not formal differential privacy without clipping, sensitivity/accounting, and a validated mechanism.
- Golden-ratio spacing, stochastic-resonance benefit, RF superiority, consciousness, AGI, biological life, cosmological claims, and extra physical dimensions are not represented as verified results absent reproducible evidence.

## Compatibility

Historical files remain at their existing Git history. Active APIs may introduce versioned formats (for example HRCS packet v2 and password-encryption envelopes) while preserving explicit legacy readers where practical. Schema migrations must be named and documented rather than silently reusing incompatible storage collections.
